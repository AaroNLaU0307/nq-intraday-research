## RULING=B —— 重述 C_BUILD_2 的断言为调用返回后可观测的形态

核心理由（按强度排序）：

1. **A 会把默认拒绝的门变成「残留制造机」。** 钩子是调在 write 与 promote 之间的
   外部代码；而这道门今天的定义就是无条件 raise。接进去的那一刻起，每次
   `resolve_partial` 都会在 staging 中途被打断，把 `.partial` 留在盘上——把 BRANCH_E
   本来处理的「崩溃残留」变成设计内必然产物。哪怕将来门改为有条件放行，
   任何一次门拒绝仍制造同一形态的残留。
2. **A 违反 R3 自己的门学说。** R3 §3（Sol 08-25 第 1 条）：门是分类器，不是校验器；
   「门内不得出现第二份不变量实现」。中途观测「FINAL 缺席 ＋ `.partial` 在场」
   恰恰是对机制按构造已保证之事做第二份实现。而 (b)(c) 两条（无删除、分歧件在场）
   本就是机制性质，已由测试与 AST 层禁 `unlink`/`rmtree`/`remove` 钉死
   ——中途观测不增加任何保护面。
3. **中途观测点不提供任何调用前拿不到的信息。** 门在调用前持有 `intended` 字节与
   `out_dir`，中途唯一新增事实是「盘上写成功」，而机制自己就复读校验了它。
   凡中途可查者，皆可在调用之前查——**且调用前拒绝能在任何 `.partial` 字节落盘之前
   拦住，严格优于中途拒绝。**
4. B 的代价可控且有既有工序承接：本项目已有 SUPERSEDES／追加节的成例
   （R3 对 R2；§10.1bis 对 §5），改措辞走同一形态即可。

### 三问逐条

**① 若选 A，原子性是否受损——受损，且不止一层。** 今天可断言的性质是：一次调用恰得
{promote 完成 · already_sealed · retry_permitted · 拒绝} 四者之一，且调用后 `.partial`
永不存活（`test_staging_promotes_atomically_and_leaves_no_partial_behind` 与
`test_c_build_2s_state_is_not_observable_to_a_caller` 正钉着）。钩子引入第五种结局
「钩内异常、中途终止、残留在盘」，该性质只能弱化为「无钩干扰时原子」——那已不是被钉住
的那条性质，**builder 那条测试必须改或删，而改一条正在承重的测试去容纳一个钩子，
正是 R2 式自相矛盾的重演。**

**② 若选 B，「不弱于」的判据**（只给判据，不给措辞）——新措辞须逐条满足五条：

```
(1) 覆盖保全：旧断言三事实各自防的违规类——.partial 字节被静默销毁 /
    未经校验的 FINAL 存在 / 分歧发生而无携带 incident_id 的分歧件——
    每一类在新形态下仍可检出，且逐类明写检出途径是「调用后文件系统事实」
    还是「被钉住的机制性质」，不得笼统合并。
(2) 证伪保全：新措辞每一子句配变异证红（把机制改成违规 → 有测试变红），
    与 R3 各节同一证据标准。
(3) 不得回并：C_BUILD_2 的主体仍须是 .partial 纪律，与 C_BUILD_1/3
    的「三条互不蕴含」钉子共存不冲突——不得向 R2 那条通用规则回退半步。
(4) 锚定保全：断言仍须从已批准值（SILENT_DELETE_FORBIDDEN=YES、
    DIVERGENT_PARTIAL_TEMPLATE、MODIFY 两分支）可导出，批准值一变即红
    （既有 premise 测试的形态）。
(5) 缺口真正出清：新措辞必须明写门将来的运行位置与职能（在调用边界上
    分类机制的结局/异常），使「接到哪里」不再是留给实现者的开放读法——
    否则 B 只是把矛盾换了措辞藏起来。
```

**③ 现在定，不推到接线时。** 三条理由：现在写的断言在无钩调用边界上按定义不可满足
——将来接线者面对一段断言假状态的文本，只能要么默默加钩（未裁的 A）、要么默默弱化措辞
（未论证的 B），两者都是「实现者自选读法」，本项目已为该形态付过两次代价；现在定最便宜
——门是桩、零执行、无任何在途封存，约束落地成本为零；且这正是 R3 §10.4 自己立的原则
——「规则先于能力落地，能力就不能在没有规则的情况下到来」。**裁定与 builder 倾向一致，
但依据独立形成。**
