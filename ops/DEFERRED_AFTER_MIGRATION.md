**本件存在的理由**：裁定把两件事推到迁移之后，并同时下了一条冻结令。
推迟的事若只写在裁定里，会随裁定一起沉底；冻结令若只写在裁定里，
下一个会话不会知道它在 force。**所以单列。**

---

## 1. 冻结令 —— 现在就在 force

```
R4 ratify 之前，禁止追加任何 CR1 行。
```

**决裁席原话**：八项授权全 NO、真实运行被边界落地前置封锁，CR1 本就无法合法触发；
**此条把「本就不会」升为「明令不得」。**

**为什么值得单写一条明令**：「本就不会」依赖三个条件同时成立（授权全 NO、
边界未落地、无真实运行）。任何一条被解除，CR1 就重新可触发，而那时没有人会记得
它依赖的是巧合而不是规则。**明令不依赖那三个条件。**

CR1 = `SUPPLEMENT_RUN_CRASH_RESOLVED`，NUMBERED，actor `main agent`，
`incident_required`，predecessors `("P3",)`，successors `("F3",)`。

## 2. R4 —— 迁移执行完成之后起草

### 为什么在之后而不是之前（决裁席附带裁定，CONFIDENCE=MEDIUM，Aaron 可另裁）

> 迁移前 N1 不存在，先签 R4 就得绑一个尚不存在的所指，**把本件缺陷再递归一层**；
> 迁移后可绑实然的 N1/O0/O1，一次成型。

**因此 R4 不是迁移的阻断项。** 窗口安全性由 §1 的冻结令承担。

### R4 必须处理的范围 —— 不止一行

决裁席明裁：**`PREIMAGE` 的仓锚定必须一并处理**，不能只改 `COLD_RECOMPUTE`。

```
问题   迁移后两个仓在同一相对路径 ops/TRIAL_REGISTRY.md 上各有一个东西：
       新仓的真 registry，旧仓的墓碑。
       锚在旧仓的冷读者会去哈希墓碑字节。
       （CRITERION 的见证超集判据随后会拒，fail-closed 兜得住，
         但诚实写入者与冷核对者两侧口径分裂本身就是缺陷。）

形式   一次性的仓锚定 —— 块内定义一次 registry 仓的身份，
       PREIMAGE 与 COLD_RECOMPUTE 都相对它解析。
       只改一行会在同一个块里留下两条不同的解析规则。

不动   registry_witness_ref 指向两仓之外的见证根，不受影响。
```

**该「一次性仓锚定」的形状出自决裁席自己，它已声明因此对该修法的未来复审独立性折减。
R4 的 Sol 复审必须被告知这一点。**

### 桥的形式：由 R4 提案定，不由裁定定

决裁席只立约束，不出机制草案（理由：出草案即成为设计贡献，丧失复审独立性）：

```
1. 桥必须可由冷读者仅凭持久字节复算（commit message 与 canonical 记录，不含任何 chat）
2. 必须引用 S4 已裁拓扑（N1 记 O0+SHA0+定位符，O1 记 N1），不得另立钉法
3. 不得要求任何历史重写
```

链条：**builder 起草 → fresh Sol 复审 → Aaron 批**。

### 「刚批准就修订」的门 —— 三条，不另发明新门

```
(a) R4 批准块显式引用被作废的 c251335f… 并写明作废理由（所指重绑定，判据未变）
    —— 与 R3 弧线每版作废前版哈希的既有惯例同形，也直接堵 M8 型
       「记录内两条活批准」的空档
(b) fresh Sol 对 R4 的复核须含正面结论「修订未实质削弱原批准」，具体为：
       PREIMAGE 读取口径 · CRITERION 超集判据 · UNRESOLVED 的 TOCTOU 披露
    除仓锚定外逐字义不变
(c) 批准仍走 §D.10.3 原路（id + sha256 + 精确 doc HEAD），不加新门类
```

### FALSIFIER（裁定原文）

## 3. 边界 (2) 接入 —— 独立事项，且仍是真实运行的前置条件

裁定条件 C4：**本次不搭迁移的车。** 三条理由（决裁席）：

```
1. 迁移本身是授权门控的精细操作，不应捆绑一个未经独立复审的生产门代码变更
2. S0/S7 的手工扫描已覆盖迁移窗口本身
3. 接入应当写在迁移后的最终拓扑上 —— 迁移后 glob 该扫哪个仓的 ops/、
   旧仓墓碑的 OneDrive 冲突副本要不要报警（应当报，那是同步苏醒的信号），
   这些设计问题在迁移前写会写两遍
```

**但裁定同时明写，且这一句不能被读丢**：

> 失败模型 §0 的「边界不落地不许再跑消耗 trial 的真实运行」**不因本裁定松动**
> —— 接入不搭车 ≠ 可以无限期不接。

```
状态   边界 (2) 代码已写、未接入（失败模型 §3 表）
后果   真实运行仍被封锁，与八项授权全 NO 相互独立
解除   接入 + 独立复审，之后才谈真实运行
```
