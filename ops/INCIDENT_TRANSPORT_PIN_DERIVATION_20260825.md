## 2. 两层错，都在我

**第一层：钉子在写下的那一刻就是假的。** 我把 `unchanged_since` 设成当时的
HEAD `d4d7c6e`。但送审集里的
`ops/N09_EXECUTION_PATH_DESIGN.md` **在那个 commit 时还不存在**——它是我随后在
`c02d5e1` 里创建的。钉一个「自某时以来未变」，而该时点上文件根本不存在，这不是
过期，是**从一开始就为假**。

**第二层，更难看：我的守卫是对的，但我在它不可能失败的时刻跑了它。**
`test_no_commit_has_touched_a_reviewed_path_since_its_declaration` 是我昨天
（同日更早）为防上一次事故建的。我的执行顺序是：

```
1. 写设计文档（untracked）
2. 登记六份，unchanged_since = 当时 HEAD
3. 跑守卫 -> 通过        <-- 此刻什么都没提交，区间必然为空
4. commit（设计文档在这个 commit 里）  <-- 区间在此变为非空
5. 交给 Sol，没有重跑
```

第 3 步的「通过」**什么也没证明**。现在（提交之后）跑同一条守卫，它立刻失败。

## 3. 三次失败，同一个形状

| # | 机制 | 当时建的守卫 | 下一次是怎么绕过去的 |
|---|---|---|---|
| 1 | 我改了复审者手上的工件 | 哈希冻结登记表 | 字节没变，但**声明**过期了 |
| 2 | 我钉了 HEAD 然后挪了 HEAD | 不会过期的 `REVIEWED_SET_UNCHANGED_SINCE` | 不变量对了，但**值是手打的**，且**验的时机不对** |
| 3 | 手打的钉子 + 在不可能失败的时刻验 | 见下 | —— |

**每一次守卫都编码了上一次失败的确切形状，而下一次从守卫没覆盖的那一侧进来。**
这句话我在第 2 次的事故记录里已经写过一遍；写过还再犯一次，说明光写下来不够。

## 4. 这次的修法：把值也拿掉，不只是把不变量修对

```python
derive_pin(repo, paths) -> str
    每条送审路径的 last-change commit，取其中最新的一个
    对从未提交过的路径 -> 拒绝
```

两个性质，缺一不可：

- **钉子不再由人给出。** 派生出来的值使
  `git log <pin>..HEAD -- <paths>` **按构造为空**。手打、过期、过早的值全部
  在 `test_the_pin_is_the_derived_one_not_a_typed_one` 里当场失败——包括那种
  恰好让区间为空的假声明（钉得太晚），区间检查对它是无感的。
- **对未提交路径的拒绝才是承重的那一条。** 它让顺序错误**不可能发生**而不只是
  可检测：你没法给一个还没进过库的文件派生 last-change commit，所以
  **送审工件必须先提交，登记表与提示词才写得出来**——而这正是让钉子为真的顺序。

新流程：

```
1. 送审工件先 commit
2. derive_pin() 派生钉子
3. 写登记表与提示词（用派生值）
4. 在一个**不碰任何送审路径**的 commit 里提交它们
   -> 钉子在自己的修复之后依然成立
```

## 7. 补记：同一份提示词的第二次 STOP —— 声明本身是靠粘贴走的

**2026-08-25 稍晚。** 上述修复（`ff2f0ca`）落地后，Sol 再次 STOP，引的却是
**旧钉子** `d4d7c6e…`——那个值在修复后的文件里**一个字都找不到**。盘上与 HEAD
的声明都是 `c02d5e1…`，历史检查为空，登记表单一钉子一致。

**结论：复审席位拿到的是粘贴过来的旧文本，不是盘上的文件。**

这暴露的是我流程里一个真实缺口，而不是任何人的操作失误：

> 我给**送审工件**做了哈希、钉子、冻结登记；
> 但**声明工件的那份文档本身**是靠粘贴传递的，无哈希、无版本。

标准传输规则写的是「聊天携带的字节永不作为真相来源」。**我把这条规则用在了
工件上，没有用在声明工件的文档上**——花了两个会话才看见。

### 处置

提示词开头新增 `READ THIS PROMPT FROM DISK BEFORE ANYTHING ELSE`：给出文件
路径，明确说「若你拿到的是粘贴文本，请打开该文件重读」，并给出一条**行号自
校验**（某行必须逐字等于当前钉子）让复审者能立刻判断手上的副本是否陈旧。

守卫 `test_a_live_prompt_tells_the_reviewer_to_read_it_from_disk` 钉住三件事：
活跃 review 的提示词必须（a）指示从盘上读、（b）带行号自校验、（c）自校验引用的
行号**确实是**声明所在的行。第三条已变异验证——把行号改错，守卫当场抓到。
**一份漂移了的自校验，本身就是另一份陈旧声明。**

### 仍未解决的那一半，如实记

提示词无法阻止自己被粘贴。自校验只能让**陈旧副本可被发现**，不能让它不发生。
真正的消除需要「粘贴的是一张小卡片（路径＋哈希），正文永远从盘上读」这类改动，
那会再叠一层自制约定——而 §6 已经说过，两次事故都发生在自制层。**是否再叠，
归 Aaron。**
