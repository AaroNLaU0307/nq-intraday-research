## 0. 一句话

`ops/TRIAL_REGISTRY.md` 是本项目的事件真相源，而它住在一棵**被 OneDrive 主动
同步**的树里。裁定是「有边界地允许」——**边界不落地，就不许再跑消耗 trial 的
真实运行。**

## 1. 致命后果只有一种，通向它的路有两条

**致命后果**：registry 里一条已发生的事件**不见了**，而文件格式完好、所有门全过。
链于是认为那次运行没开始过，**授权第二次运行 ⇒ 双重暴露**。

### 通道 A —— 同步冲突静默回退

OneDrive 解决冲突时把 canonical 文件换回追加前的版本，把追加挪进冲突副本。
回退后的文件**格式完好**，逐行解析全过。

### 通道 B —— 半写／截断（**Fable 的裁定文本少算了这一条，builder 复核补上**）

裁定原文说「半写行会死在六格解析上……fail-closed」。**实测不成立**：

| 事实 | 位置 |
|---|---|
| 格数不符的行是 **`continue`，不是 raise** —— 畸形行被**静默丢弃** | `scripts/s0_real_run.py:183-184` |
| `ops/TRIAL_REGISTRY.md` **被 clean gate 白名单豁免**，registry 变脏**不打红** `git_clean` | `:113`，用于 `:596` `_clean_gate_exempt` |

**所以一次把末行截断的半写，其可观测状态与通道 A 完全相同。**

### 不是通道的（这两条确实 fail-closed）

- **冲突副本文件**：是**另一个文件名**的未跟踪文件，`_clean_gate_exempt` 只豁免
  精确路径 `ops/TRIAL_REGISTRY.md`，所以它会打红 `git_clean`。**成立。**
- **行内容被改写成非法词表**：`parse_registry_events` 之后的词表与语法校验会拒。

## 2. 边界 (1) 是两条通道唯一的共同拦截点

反回退见证记录 `{sha256, 事件计数, 末行}`：

- 通道 A 回退 ⇒ 事件计数低于见证 **且** 见证的末行不在 registry 里 ⇒ 拒绝。
- 通道 B 丢行 ⇒ **同样**让计数低于见证 ⇒ 拒绝。

> **给未来的人一句话**：若有人提议削减边界 (1)，理由是「反正解析器挡得住半写」，
> **那个前提是假的**（§1 通道 B）。边界 (1) 一撤，两条通道同时敞开。

## 3. 四条边界

| # | 边界 | 状态 |
|---|---|---|
| (1) | 反回退见证：每次 registry 追加后把 `{sha256, 事件计数, 末行}` 写到**非同步的受治理根**下（append-only）；每次 bootstrap 与 pre-exposure recheck 比对，registry 事件集不是最近见证的超集 ⇒ 拒绝 | 代码已写，**未接入**；见证根**待授权** |
| (2) | 冲突副本点名检测：对 `ops/` 下 `TRIAL_REGISTRY*` 非精确名 glob，命中即拒绝 | 代码已写，**未接入** |
| (3) | 提交纪律：registry 追加与 `git commit` 作为**一个操作步骤**，最小化未提交窗口，git 历史作仲裁 | **本件 §4 即是** |
| (4) | 文档化故障模型与恢复程序 | **本件即是** |

**四条是一个包。** builder 刻意没有单发 (2)——单发会制造「已经防住了」的错觉，
而真正的共同拦截点是 (1)。

## 4. 边界 (3)：提交纪律（现行有效）

1. 任何向 `ops/TRIAL_REGISTRY.md` 的追加，**与其 `git commit` 属同一操作步骤**，
   中间不插入别的工作。
2. 未提交窗口内**不得**关闭会话、不得切分支、不得让机器进入睡眠。
3. 仲裁顺序：**git 历史 > 见证 > 工作区文件**。三者不一致 ⇒ STOP，走 §5。
4. 运行器在 run 期间的追加不适用第 1 条（进程内无法 commit），由边界 (1) 的
   见证覆盖——**这正是见证存在的理由**。

## 5. 恢复程序（检出即 STOP）

**任何一条边界报警 ⇒ 立即停止，不得「先修一下再说」。**

1. **不写任何东西。** 尤其不要「把丢的行补回去」——那是一次 registry 写入，
   按第 6 项纪律必须逐 incident 经 Aaron 授权。
2. **取证**，按仲裁顺序：`git log -p -- ops/TRIAL_REGISTRY.md` 的最后若干版本；
   见证文件尾部；`ops/` 下所有 `TRIAL_REGISTRY*` 文件的字节与哈希。
3. **判型**：回退（通道 A，多半伴随冲突副本）／截断（通道 B，末行残缺）／
   两者皆非（则是别的缺陷，另开事故）。
4. **报给 Aaron**，附取证。**修复写入需要他逐 incident 的明示授权**，与
   第 6 项的 `recovery_authorization_doc` 同一形状。
5. **在裁定之前，一切消耗 trial 的真实运行保持拒绝。**
