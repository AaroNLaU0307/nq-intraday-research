## ITEM=第 1 件 · S5 回滚副本的形式

```
RULING=GIT_ONLY
```

**并明说：这是对不变量 4 修改条的修订，不是解释。** 原修改条给出的形式（改名副本
`ops/TRIAL_REGISTRY.pre-migration.<date>.md`）作废，因为它与边界 (2) 按构造相撞。
修订后的不变量 4 为：逐字节副本保留由 **(i)** 旧仓 git 历史中 O0 所含的 registry blob
（自动保留、内容寻址、历史不可重写）与 **(ii)** 新仓中经 `== SHA0` 核 verified 的那份
共同承担；**不在任何工作区创建第二份可读副本**；回滚 = 从 O0 做字节级取回并核 `== SHA0`，
不需要任何新授权（与原不变量 4 的授权条款一致）。

### 三问逐条

**① git 历史算不算「逐字节副本保留」——算，而且它不是可选项。** 关键事实是：
**三个选项下旧仓 git 历史都保留着迁移前字节**——O0 提交里的 blob 就是那份字节的逐字节副本，
存在磁盘对象库里，内容寻址钉死，历史重写被常设禁令封死。保留与否从来不是选择题；
真正的选择只是「要不要**再**造一份工作区可读副本」。所以 GIT_ONLY 不是与裁定相抵，
而是它的更强形式：C3 从「靠命名与位置」变成机制性的（磁盘上没有第二份可读 registry），
且原裁定改不变量 4 的理由——「陈旧真 registry 是最危险的形态」——本身就反对**任何**
可读陈旧副本，不只反对原路径上那份。RENAME_OUT 只是把危险换了个地址。

**② 墓碑机制能否承担 C3——能，承担原路径那一半；副本那一半在 GIT_ONLY 下无物可担。**
具名标记 `REGISTRY_MOVED_NOT_A_REGISTRY` 点名拒绝（变异证红），加上不变量 5 已把四处
生产构造收敛到 `registry_boundary`、守卫扩到 `scripts/`，机械读者全部经过拒绝点；
人类读者在原路径读到的是显式「已迁移」标记而非陈旧事件集。原路径的 C3 由墓碑承担，成立。
副本位置本须承担的那部分，在 GIT_ONLY 下消失——没有副本，无可误认。

**③ 边界 (2) 不搭这次的车。** 三条理由：迁移本身是授权门控的精细操作，不应捆绑一个
未经独立复审的生产门代码变更（fail-closed 方向）；S0/S7 的手工扫描已覆盖迁移窗口本身；
接入应当**写在迁移后的最终拓扑上**——迁移后 glob 该扫哪个仓的 `ops/`、旧仓墓碑的
OneDrive 冲突副本要不要报警（应当报，那是同步苏醒的信号），这些设计问题在迁移前写会写两遍。
**但附一条：** 失败模型 §0 的「边界不落地不许再跑消耗 trial 的真实运行」不因本裁定松动
——接入不搭车 ≠ 可以无限期不接。

### CONDITIONS（四条全部为强制）

1. **S0 增加一项核证**：`git show O0:ops/TRIAL_REGISTRY.md` 的字节 == 工作区字节 == SHA0。
   registry 被 clean gate 白名单豁免，历史副本与磁盘副本可能不一致而不打红——不核这一条，
   GIT_ONLY 的前提就是未经验证的。不等 ⇒ 存在未提交追加 ⇒ 边界 (3) 已被破坏 ⇒ STOP。
2. **回滚步骤必须重写为字节级取回**：用 binary-safe 方式从 O0 取 blob（不得信任裸
   `git checkout`——Windows 上 autocrlf/.gitattributes 可在检出时改写 LF-only 文件），
   取回后重算 sha256 必须 == SHA0，不等 ⇒ STOP 上报，不得「先修一下再说」。§7 回滚节
   现行文本引用已作废的文件名，须随之重写；回滚窗口 ≥ 一个完整工作周期不变。
3. 墓碑要求一字不减：原路径墓碑与具名标记拒绝照旧。
4. 边界 (2) 本次不接入；接入立为独立事项，且仍是真实运行的前置条件。

```
FALSIFIER   若条件 1 的核证失败（O0 提交字节 ≠ 工作区字节且不可归因于可修复的
            未提交追加），GIT_ONLY 前提坍塌 —— 回退选项是 NEW_REPO_ONLY，
            不是 RENAME_OUT（文件名撞边界的缺陷与此无关，仍然成立）。
CONFIDENCE  HIGH（方向）；条件 1、2 为裁定的组成部分，缺一即非本裁定。
```

**为什么不取另两个**：NEW_REPO_ONLY 可行但严格更弱——它把回滚押在一个刚 init、
备份合同尚未就位（S8 目标仓创建还需独立授权）的仓上，而 GIT_ONLY 的主源已存在整个仓龄，
且字节另有 S1 见证、SHA0、新仓副本三路交叉钉。RENAME_OUT 解了 C2 但 C3 靠约定，
且在同一棵 OneDrive 树里多放一份可读陈旧 registry——它唯一的真实功能（回滚冗余）
git 历史与新仓已经提供。

## ITEM=第 2 件 · CR1 所指已移

```
RULING=必须 R4
```

治理缓解不够。三条理由：

1. **它没通过被缓解对象自己的标准。** `c251335f…` 里 `COLD_RECOMPUTE` 的全部意义是
   **冷读者仅凭 canonical 字节可复算**。Aaron 批准文本里的一句指名，冷读者拿着语法块
   根本够不到——迁移后「git history of ops/TRIAL_REGISTRY.md」在旧仓终止于墓碑、
   在新仓始于 N1，块内没有任何一个字节告诉冷读者去哪个仓。语义漂了而字节没漂，
   恰恰是这个块要防的那类事。
2. **「批准语义靠 prose 而非字节承载」是本项目付过学费的同型缺陷**——§D.11.3
   「声称已机械化、实则从未有过」、M8 空档（批准记录内部自相矛盾而守卫看不见）。
   整个 R3 弧线就是在把语义绑进字节；在 CR1 上开一个「哈希稳定、语义漂移」的例外，
   会让「字节没变」不再是「含义没变」的证据，动摇整个哈希绑定制度。
3. **无活的反方。** 前席自陈这是最弱处并预先不反对 R4；复审席判必须；builder 倾向必须。
   唯一省下的是一次签字，而前席承认那正是它的动机。

### 若 R4，三问逐条

**① 不止 `COLD_RECOMPUTE` 一行——`PREIMAGE` 的仓锚定必须一并处理。**
`CR1_REGISTRY_INTACT_PREIMAGE` 说「the complete on-disk bytes of ops/TRIAL_REGISTRY.md」
——迁移后**两个仓在同一相对路径上各有一个东西**：新仓的真 registry 与旧仓的墓碑。
锚在旧仓的冷读者会去哈希墓碑字节（CRITERION 的见证超集判据随后会拒，fail-closed 兜得住，
但诚实写入者与冷核对者两侧口径分裂本身就是缺陷）。正确形式是**一次性的仓锚定**：
块内定义一次 registry 仓的身份，`PREIMAGE` 与 `COLD_RECOMPUTE` 都相对它解析。
只改一行会在同一个块里留下两条不同的解析规则。`registry_witness_ref` 指向两仓之外的
见证根，不受影响，不动。

**② 桥的形式由 R4 提案定，不由本裁定定。** 桥的既有基材就是 S4 已裁的交叉互钉
（N1 记 O0+SHA0+定位符，O1 记 N1）。本席只立约束：桥必须可由冷读者仅凭持久字节复算
（commit message 与 canonical 记录，不含任何 chat）；必须引用 S4 已裁拓扑而非另立钉法；
不得要求任何历史重写。具体形式 builder 起草、Sol 复审、Aaron 批。**理由**：决裁席出
机制草案会重演前席在边界②上自己披露过的陷阱——设计贡献即丧失对该修法的未来复审独立性。

**③ 「刚批准就修订」的门：采纳前一份裁定的备案答案，两条都要，不另发明新门。**
(a) R4 批准块显式引用被作废的 `c251335f…` 并写明作废理由（所指重绑定，判据未变）
——与 R3 弧线每版作废前版哈希的既有惯例同形，也直接堵 M8 型「记录内两条活批准」的空档；
(b) fresh Sol 对 R4 的复核须含正面结论「修订未实质削弱原批准」——具体为：`PREIMAGE`
读取口径、`CRITERION` 超集判据、`UNRESOLVED` 的 TOCTOU 披露，除仓锚定外逐字义不变；
(c) 批准仍走 §D.10.3 原路（id + sha256 + 精确 doc HEAD），不加新门类。

**时序（附带裁定，CONFIDENCE=MEDIUM，Aaron 可另裁）**：R4 在**迁移执行完成之后**起草
——迁移前 N1 不存在，先签 R4 就得绑一个尚不存在的所指，把本件缺陷再递归一层；
迁移后可绑实然的 N1/O0/O1，一次成型。窗口安全性由一条冻结令保证：
**R4 ratify 之前，禁止追加任何 CR1 行**（八项授权全 NO、真实运行被边界落地前置封锁，
CR1 本就无法合法触发；此条把「本就不会」升为「明令不得」）。R4 因此不是迁移的阻断项。

```
FALSIFIER   若 R4 起草时发现 S4 交叉互钉不足以让冷读者单凭字节完成跨仓解析
            （即桥必须引入 S4 之外的新钉法），本裁定「桥引用 S4 即可」的
            前提即被证伪，桥的设计须回到决裁层重裁而非在 R4 内自行扩权。
CONFIDENCE  必须 R4：HIGH。时序与冻结令：MEDIUM。
```
