## 1. 处置：不是收窄措辞，是修 walker

席位说最小改法是把「路径级」收窄成「出口位点级」，并把折叠记成
`ACCEPTED_BY_CAP` 残留；是否重做仪器由 Aaron 按上限决定。

**我选择修，因为根因已经被指出来了，而「明知怎么修却只改措辞」
不是上限该保护的东西。** 上限管的是**复审轮数**，不是我拒绝修一个我会修的缺陷。

### 1.1 walker 现在在每个「会落空」的分支处分叉剩余语句

```
分支若在所有路径上都退出   -> 无剩余
分支若落空                 -> 把函数其余部分带上，按该分支的 guard 各走一遍
```

`_always_exits` 只看最后一条语句（对无循环、语句世界封闭的函数是精确的），
**且失败方向是安全的**：把「会退出」误判成「会落空」只会多出一条没人能执行的
声明路径，而覆盖断言会报出来，不会掩盖。

**12 条声明变 17 条。没有一条是新代码路径**——它们一直可执行，只是被算作了别人。

新出现的五条正是被折叠的那些：`promote`、`supplement_partial_verify`、
post-promotion verify 各自「已有同字节残留」与「本次刚写入」两版。

### 1.2 身份改成路径本身，两侧仍然全部导出

```
声明侧   walk 到达该出口时经过的语句行集合（＋ helper 内 raise 行）
运行侧   sys.settrace 在 resolve_partial 帧内记录的行（＋ traceback 的 helper 行）
判据     声明路径的行全部出现在 trace 中，且匹配唯一
```

**「唯一」是承重的**：两条声明同时匹配一条 trace，意味着身份又折叠了 ——
那是失败，不是静默通过。

行集合不要求相等，只要求包含，原因是**实测出来的两条系统性差异**：
tracer 报 `def` 行而 walker 报第一条语句（docstring），多行 `raise` 的续行 tracer 会报。
docstring 行按导出方式剔除，不是手写常量。

### 1.3 一条驱动缺陷，是修的过程中量出来的

`partial` 在「已有同字节残留」时被读**两次**（一次定分支 C，一次校验落盘）。
我的说谎读连第一次也骗，于是调用直接走去分支 C，
**那三条 fall-through 尾部的声明路径看起来不可达**。
改成从第 N 次读起说谎后，17 条全部命中。

### 1.4 变异证红 —— 用席位的原案

从生成器删掉 `("absent", "intended")`：

```
declared by the contract and executed by nothing here:
  ('promote', [995, 996, 997, 998, 1000, 1009, 1010, 1011, 1020, 1026, 1027, 1031], None)
```

**正是被折叠的那条路径，被点名。** R8 送审的那一版对同一删除是全绿。

## 2. 席位对我 §5 归因的更正 —— 我错了，方向是**把弱点写得比事实宽**

我在 §5 写：

> 观测器只包四个名字…**绕过它就同时绕过因果那一半**

席位说不准确：因果测试用的是**独立的说谎读干预**，
提前绑定 `Path.read_bytes` 会让该测试**变红**，不是静默绕过。

**我实测了两次。**

```
第一次（我的注入不成立）  函数入口 _early = Path.read_bytes   -> 22 passed
                          调用时求值，那时测试已打好补丁，等于没绑
第二次（真正的提前绑定）  模块导入期 _READ_AT_IMPORT = ...     -> 4 failed
                          含 test_a_lying_read_changes_the_answer 被点名
```

**席位是对的。** 该残留应写成「调用计数／effect 观测的机制限制」，
而不是「因果可被静默绕过」。

值得记一句：这一晚我反复把**声称写得比事实宽**；这一条是把**弱点**写得比事实宽。
方向相反，成因相同——**没量就断言**。
